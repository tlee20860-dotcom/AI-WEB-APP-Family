# C-02 通用規則（跨專案）

最後更新：B30-9
版本：v1.7
用途：所有專案的通用協作規則

---

## 零、Token 不足處理

**原則**：交付前若預估 token 不足，**不得自主交付刪減版**。

| 情境 | 判斷 | AI 動作 |
|---|---|---|
| Token 足夠 | 本次可完整交付 | 交付完 → 問「是否繼續交付第 N 批？」 |
| Token 不足 | 本次無法完整交付 | 提示 + 提供新對話開場白 |

**禁止**：自主刪減、未說明分批、交付未完整、降低品質。

## 零點五、Token 視覺化

| Emoji | 剩餘 | 行為 |
|---|---|---|
| 🟢 | ≥ 50% | 正常交付 |
| 🟡 | 20~49% | 提示偏低 |
| 🔴 | < 20% | 提供新對話開場白 |

**格式**：`Token: {emoji} [{bar}] {pct}% 剩餘`

## 一、核心原則

| # | 原則 | 說明 |
|---|---|---|
| 1 | 先方案後交付 | 未確認不交付 |
| 2 | 最小改動優先 | 5 問自檢 |
| 3 | 極簡優先 | 能 1 檔不改 2 檔 |
| 4 | SSOT 極大化 | 邏輯集中 1 處 |
| 5 | AI 優先 | 為 AI 可讀性優化 |

---

## 二、問題處理流程

| 步驟 | 動作 |
|---|---|
| 1 | 診斷（根本原因） |
| 2 | 建立對照組（見 C-07 §二） |
| 3 | 跑 5 問自檢 |
| 4 | 提供「方案 + 對比表」 |
| 5 | 待使用者確認 |
| 6 | 確認後才交付 |

---

## 三、主動提案義務

| 情境 | AI 應做 |
|---|---|
| 看到更好方案 | 主動提出 |
| 決策不合理 | 明確反對並說明 |
| 使用者方案不理想 | 誠實告知「理想化」 |
| 發現漏洞 | 主動指出 |

---

## 四、5 問自檢

| # | 問題 | 若答「是」 |
|---|---|---|
| 1 | 能不能只改 1 檔？ | 到此為止 |
| 2 | 能否改集中層？ | 改集中層 |
| 3 | 各檔改動可否用「預設值」吸收？ | 呼叫端不動 |
| 4 | 可否加參數（向後相容）解決？ | 舊呼叫不動 |
| 5 | 現有架構是否已提供切入點？ | 用現有 |

**交付摘要必附 3 欄位**：改動檔案數 / 最小改動路徑 / 為何不是 N-1。

---

## 五、禁止事項

| 禁止 | 說明 |
|---|---|
| 猴子補丁 | 改引擎不改呼叫端 |
| 加快取變數判斷資料 | 用 onDataChange |
| 從現況推論範圍 | 從理想設計推論 |
| 把「統一」誤解為「各頁都改」 | 統一 = 邏輯集中 |
| 未掃描就估檔數 | 先掃描 |
| 為避免新增檔案而妥協 | 該新增就新增 |
| 為人類可讀性犧牲簡潔 | AI 優先 |
| 交付含嵌套未用外層 +1 | 見第六節 |
| 未顯示 Token 狀態 | 見零點五節 |

## 六、檔案規則

| 規則 | 說明 |
|---|---|
| 檔案 ≤ 500 行 | 超過拆檔 |
| 檔案結束標記 | END OF FILE（必加） |
| 交付完整 | 不用 diff / 「...」 |
| 每檔獨立 | 不合併 code block |
| backtick 嵌套 | 外層 = 內層 + 1 |

**backtick 嵌套強制檢查**：

| 步驟 | 動作 |
|---|---|
| 1 | 掃描內層 backtick 數 |
| 2 | 外層 = 內層最多 + 1 |
| 3 | 交付摘要標示「嵌套檢查 ✅」 |

| 情境 | AI 動作 |
|---|---|
| 對話結束 | 檢查是否有新經驗 |

**記憶提升**：

| 層級 | 檔案 | 上限 |

| L1 工作記憶 | 當前對話 | — |
| L2 短期 | C-05-learning.md | 100 行 |
| L3 長期 | C-01 / C-02 | 150 / 200 行 |

## 十六、上傳檔案自我檢查（🆕 B30-9）

**觸發情境**：使用者手動上傳檔案到 GitHub（尤其是 Spck Editor、GitHub 網頁版）。

**強制檢查**（每次推送前）：

| # | 檢查項 | 說明 |
|---|---|---|
| 1 | 檔名 ↔ 內容 對應 | 確認貼上的代碼與檔名相符 |
| 2 | Commit 已 Push | 確認所有 Commit 都推送到遠端 |
| 3 | 多檔一起推送時 | 逐一核對每個檔案內容，避免互相覆蓋 |
| 4 | 版本號 | 確認檔案內版本號已更新 |

**AI 職責**：

| 情境 | AI 動作 |
|---|---|
| 使用者說「已部署」但功能未變 | 先問「是否確認每個檔案內容正確？」 |
| 多次清快取無效 | 先懷疑「檔案是否真的上傳成功」 |
| 使用者反饋「檔案內容一樣」 | 提醒檢查 Spck Editor 的複製貼上 |

**禁止**：在未確認檔案正確上傳前，反覆要求使用者清快取。
