## 零、Token 不足處理

**原則**：交付前若預估 token 不足，**不得自主交付刪減版**。

| 情境 | 判斷 | AI 動作 |
|---|---|---|
| Token 足夠 | 本次可完整交付 | 交付完 → 問「是否繼續？」 |
| Token 不足 | 本次無法完整交付 | 提示 + 提供新對話開場白 |

**禁止**：自主刪減、未說明分批、交付未完整、降低品質。

## 零點五、Token 視覺化

| Emoji | 剩餘 | 行為 |
|---|---|---|
| 🟢 | ≥ 50% | 正常交付 |
| 🟡 | 20~49% | 提示偏低 |
| 🔴 | < 20% | 提供新對話開場白 |

**格式**：Token: {emoji} [{bar}] {pct}% 剩餘

## 四、5 問自檢

| # | 問題 | 若答「是」 |
|---|---|---|
| 1 | 能不能只改 1 檔？ | 到此為止 |
| 2 | 能否改集中層？ | 改集中層 |
| 3 | 各檔改動可否用「預設值」吸收？ | 呼叫端不動 |
| 4 | 可否加參數（向後相容）解決？ | 舊呼叫不動 |
| 5 | 現有架構是否已提供切入點？ | 用現有 |

**交付摘要必附 3 欄位**：改動檔案數 / 最小改動路徑 / 為何不是 N-1。

## 五、禁止事項

| 禁止 | 說明 |
|---|---|
| 猴子補丁 | 改引擎不改呼叫端 |
| 加快取變數判斷資料 | 用 onDataChange |
| 從現況推論範圍 | 從理想設計推論 |
| 把「統一」誤解為「各檔都改」 | 統一 = 邏輯集中 |
| 未掃描就估檔數 | 先掃描 |
| 為避免新增檔案而妥協 | 該新增就新增 |
| 交付含嵌套未用外層 +1 | 見 §六 |
| 未顯示 Token 狀態 | 見 §零點五 |

## 六點五、兩層三反引號規則（強制）

**核心**：分「外層」與「內層」。

### 6.5.1 外層（AI 交付時）

| 情境 | 寫法 |
|---|---|
| AI 交付任何檔案內容 | **必須用三反引號包裹** |
| 目的 | 提供「一鍵複製」按鈕 |

**禁止**：直接寫（不包裹）。

### 6.5.2 內層（md 檔案內部）

| 情境 | 寫法 |
|---|---|
| md 內展示格式 / 範例 | 引用塊（`>`） |
| md 內單行關鍵字 | 行內單反引號 |
| md 內結構化內容 | markdown 表格 |
| md 內真代碼 | 另存獨立檔案 |

**禁止**：md 內用三反引號。

**理由**：md 內的 ``` 會被渲染成灰框，干擾閱讀。

### 6.5.3 內層（真代碼檔案）

| 情境 | 寫法 |
|---|---|
| .js / .html / .css 內含 ``` | 正常 |
| .js 內含 ``` 範例 | 外層 = 內層 + 1 |

### 6.5.4 記憶口訣

- **「外面」（交付）** → 要 ```（一鍵複製）
- **「裡面」（md 內容）** → 不要 ```（渲染乾淨）

## 八、交付必遵守 9 條（強制）

| # | 規則 |
|---|---|
| 1 | 每次回覆標 🆔 編號 #序號 |
| 2 | 交付時 EOF 記 F/V/B/W |
| 3 | 每次交付附「本對話追蹤表」 |
| 4 | 批次結束輸出 P-11-writers 完整版 |
| 5 | 被問「某檔最後編寫」→ 回時間 + Writer + ReplyNo |
| 6 | 舊紀錄移歷史，不刪 |
| 7 | 每 20 條回覆輕量自檢（格式一致性） |
| 8 | 每 50 條回覆完整重讀 C-00 + C-02 |
| 9 | Version 一律用 Unix epoch（10 位數字） |

**違反任一條 → 使用者可要求重新交付。**

## 九、編號規則（強制）

### 9.1 對話編號

格式：A{YYYYMMDD}-{序號3位}

| 範例 | 說明 |
|---|---|
| A20261013-001 | 第 1 個對話 |
| A20261013-002 | 同日第 2 個 |

### 9.2 回覆序號

格式：#001 ~ #999（同對話累加）

### 9.3 生成流程

| 情境 | 動作 |
|---|---|
| 有 P-11-writers | 取最新 +1 |
| 無 P-11-writers | 自建第一筆並交付 |

## 十七、上傳檔案自我檢查

**觸發情境**：使用者手動上傳檔案到 GitHub。

**強制檢查**（每次推送前）：

| # | 檢查項 |
|---|---|
| 1 | 檔名 ↔ 內容 對應 |
| 2 | Commit 已 Push |
| 3 | 多檔一起推送時逐一核對 |
| 4 | Version 已更新 |

**AI 職責**：

| 情境 | AI 動作 |
|---|---|
| 使用者說「已部署」但功能未變 | 先問「是否確認每個檔案內容正確？」 |
| 多次清快取無效 | 先懷疑「檔案是否真的上傳成功」 |
| 使用者反饋「檔案內容一樣」 | 提醒檢查複製貼上 |

**禁止**：在未確認檔案正確上傳前，反覆要求使用者清快取。
