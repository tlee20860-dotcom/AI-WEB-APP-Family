## 一、階段性總結（Stage Summary）

### 1.1 觸發詞

使用者說「階段性總結」。

### 1.2 強制動作

| 步驟 | 動作 |
|---|---|
| 1 | 讀 P-03 找上次總結標記 |
| 2 | 讀 C-05 取新教訓 |
| 3 | 讀 C-06 更新 Token 記錄 |
| 4 | 回顧本次對話 |
| 5 | 更新 5 檔（C-05 / C-06 / P-03 / P-12 / P-04） |
| 6 | 標記「本次階段性總結 @ B{批次}」 |
| 7 | 生成進化報告供確認 |

### 1.3 觸發訊號（依可靠度排序）

| 優先 | 訊號 |
|---|---|
| 1 | AI 開始失誤（忘記路徑、重複問、未查 docs） |
| 2 | 客觀工作量（上傳 + 交付 ≥ 10 檔，或對話 ≥ 30 輪） |
| 3 | 任務切換 ≥ 3 個 |
| 4 | Token 剩餘偏低（僅參考） |

---

## 二、對照組強制（最高優先）

**原則**：遇到「單一帳號、單一裝置、單一頁面」異常時，**必須先建立對照組**。

| 異常類型 | 對照組做法 |
|---|---|
| 單一帳號異常 | 用全新帳號（或無痕 + 新帳號）登入 |
| 單一裝置異常 | 換另一台裝置 |
| 單一頁面異常 | 訪問其他同類頁面 |

**判斷**：

| 對照組結果 | 結論 |
|---|---|
| 正常 | 100% 是原狀態快取卡死，放棄原狀態 |
| 也異常 | 系統級問題，繼續排查 |

---

## 三、路徑問題強制前置

任何涉及「檔案路徑 / 資料夾結構」的建議，**必須先查 docs**。

| 步驟 | 動作 |
|---|---|
| 1 | grep P-02 §十 + P-04 |
| 2 | 若未記載 → 先補 docs，再回答 |
| 3 | 若與實際不符 → 先提醒，再修正 |
| 4 | 禁止憑印象回答路徑 |

---

## 四、輕量審視（新對話用）

| 觸發 | 動作 |
|---|---|
| 新對話要改的檔案，是上一輪交付過的 | 必須先審視上一輪交付 |
| 新對話是全新獨立任務 | 不需審視 |
| 階段性總結 | 一律審視 |

**目的**：兼顧安全與效率，避免每輪都背沉重歷史。
