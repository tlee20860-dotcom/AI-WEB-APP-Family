# C-03 流程指南

最後更新：B29-10a
版本：v1.2
用途：AI 執行流程 + 決策樹

---

## 一、開場 SOP

**AI 讀 C-00-startup 後**：

| 步驟 | 動作 |
|---|---|
| 1 | 回報「已讀取 startup」 |
| 2 | 列 4 選項 |
| 3 | 待使用者選擇 |

**使用者選後**：

| 情境 | AI 動作 |
|---|---|
| 新專案 | 請求 C-01~C-05 |
| 舊專案 | 請求 C-01~C-05 + P-* 全部 |
| 純討論 | 直接討論 |
| 其他 | 依說明 |

## 二、讀取決策樹

| 3 | P-03-progress |

| 步驟 | 讀取 |

| 5 | 待確認 |

### 使用者說「新增功能」

| 步驟 | 讀取 |
|---|---|
| 1 | C-02-rules §四（5 問） |
| 2 | P-04-manifest |
| 3 | 跑 5 問自檢 |
| 4 | 提供方案（含檔數 + 最小路徑） |
| 5 | 待確認 |

### 使用者說「改版面」

| 步驟 | 讀取 |
|---|---|
| 1 | C-02-rules |
| 2 | P-07-pagemap 版面章節 |
| 3 | 相關 P-* UI 檔 |
| 4 | 跑 5 問自檢 |
| 5 | 列變更對照 |
| 6 | 待確認 |

## 三、上下文路由（AI 自動判斷）

| 使用者在做 | AI 自動讀 |
|---|---|
| 準備交付 | P-99-errors-map |
| 討論架構 | P-02-anchor |

## 四、三層讀取策略

| 層級 | 檔案 | 讀取時機 |
|---|---|---|
| L1 必讀 | C-00 ~ C-05 | 每次對話 |
| L2 概覽 | P-01 ~ P-04 | 舊專案啟動時 |
| L3 細節 | P-05 ~ P-98 | 按需（AI 判斷） |
| 特殊 | P-99-errors-map | 交付前必讀 |

## 五、對話流程（典型）

| 步驟 | 誰 | 動作 |
|---|---|---|
| 1 | 你 | 上傳 C-00-startup |
| 2 | 你 | 貼「請讀取 docs/」 |
| 3 | AI | 讀 + 列 4 選項 |
| 4 | 你 | 選情境 |
| 5 | AI | 請求對應檔案 |
| 6 | 你 | 上傳 |
| 7 | AI | 讀 + 回報狀態 |
| 8 | 你 | 說明需求 |
| 9 | AI | 跑 5 問 → 提供方案 |
| 10 | 你 | 確認 |
| 11 | AI | 交付 |
| 12 | 你 | 測試回報 |
| 13 | AI | 修正或完成 |
| 14 | AI | 對話結束前綜合記憶 + 顯示 Token |

## 六、中途切換情境

**使用者說「切換情境」**：

| 步驟 | AI 動作 |
|---|---|
| 1 | 確認「放棄當前情境？」 |
| 2 | 重列 4 選項 |
| 3 | 依新情境走 |

## 七、對話結束記憶綜合

**觸發時機**：

| 觸發 | 動作 |
|---|---|
| 使用者說「結束對話」 | 執行綜合 |
| 使用者說「再見 / 之後再說」 | 執行綜合 |
| AI 感知對話自然結束 | 主動建議 |

**執行步驟**：

| 步驟 | 動作 |
|---|---|
| 1 | 回顧本次對話 |
| 2 | 提取新經驗（Reflexion 格式） |
| 3 | 寫入 C-05-learning |
| 4 | 若達閾值 → 建議提升 |
| 5 | 生成「進化報告」 |
| 6 | 待確認後更新 |

---

## 八、新專案骨架判斷

**AI 依描述判斷**：

| 專案特徵 | 建議檔數 |
|---|---|
| 純靜態 / 單頁 | 2 檔 |
| 有狀態 / 多頁 | 4 檔 |
| 有架構 / 多模組 | 6 檔 |
| 複雜 / 多人協作 | 全部 |

**AI 主動說明 → 使用者確認 → 才建檔**。

## 九、常見錯誤（禁止）

| 錯誤 | 正確 |
|---|---|
| 未經確認直接改檔 | 先方案 |
| 直接估算 N 檔 | 先掃描 |
| 從現況推論範圍 | 從理想推論 |
| 忽略使用者偏好 | 讀 C-01 |
| 忘記記錄教訓 | 對話結束綜合 |
| 忘記顯示 Token 狀態 | 見 C-02 §0.5 |

## 十、動作模板（4 個）

### 模板 1：交付檔案

| 部分 | 內容 |
|---|---|
| 檔案路徑 | 標題 `## 📁 檔案路徑` + 獨立 code block |
| 檔案內容 | 標題 `## 📄 檔案內容` + code block |
| END OF FILE | 每檔最後 |

**含內層 code block**：外層 backtick = 內層 + 1

### 模板 2：交付批次

| 部分 | 內容 |
|---|---|
| 批次標題 | `# 📦 B{nn}：第 {N} 波（{X} 檔）` |
| 版本資訊 | 版本 + 批次 |
| 逐檔交付 | 依模板 1 |
| 交付摘要 | 表格 |
| 最小改動對比 | 表格 |
| 交付前自我檢查 | 表格 |
| 下一步 | 說明 |
| **Token 狀態** | **回覆結尾顯示** |

### 模板 3：更新清單

| 部分 | 內容 |
|---|---|
| 目前批次 | 列已交付批次 |
| 詢問 | 請回覆已部署到哪個批次？ |
| 收到回覆後 | 列該批次後所有最新版檔案 |

### 模板 4：問題診斷

| 部分 | 內容 |
|---|---|
| 症狀 | 使用者描述 |
| 根本原因 | 深層 |
| 5 問自檢 | 最小改動分析 |
| 方案 | 多選項 + 建議 |
| 待確認 | 使用者回覆 |

## 十一、常見問題 FAQ（Q1~Q14）

### Q1：使用者提供的檔案不完整

| 面向 | 動作 |
|---|---|
| 判斷 | 上傳被截斷 |
| 動作 1 | 列「缺少哪份」 |
| 動作 2 | 請重新上傳 |

### Q2：使用者要求的功能與現有衝突

| 面向 | 動作 |
|---|---|
| 動作 1 | 指出衝突 |
| 動作 2 | 提供 2-3 個替代方案 |
| 動作 3 | 待確認 |

### Q3：使用者要求超出規則（如：檔案 > 500 行）

| 面向 | 動作 |
|---|---|
| 動作 1 | 指出違規 |
| 動作 2 | 提供拆分方案 |
| 動作 3 | 待確認 |

### Q4：使用者要求用 diff 交付

| 面向 | 動作 |
|---|---|
| 動作 1 | 說明規則（C-04 六） |
| 動作 2 | 提供完整檔案 |
| 動作 3 | 若堅持 diff → 記錄為例外 |

### Q5：使用者要求新增檔案但可複用現有

| 面向 | 動作 |
|---|---|
| 動作 1 | 指出可複用 |
| 動作 2 | 提供「擴充現有」方案 |
| 動作 3 | 待確認 |

### Q6：交付時 backtick 嵌套問題

| 面向 | 動作 |
|---|---|
| 動作 1 | 數內層 code block 的 backtick 數量 |
| 動作 2 | 外層用 N + 1 個 |
| 動作 3 | 若無法判斷 → 用表格說明規則 |

### Q7：文檔寫作原則違反

| 面向 | 動作 |
|---|---|
| 動作 1 | 檢查是否用 code block 示範 code block |
| 動作 2 | 若違反 → 改用表格 |
| 動作 3 | 檢查是否重複 anchor 規則 |

### Q8：使用者要求刪除區塊

| 面向 | 動作 |
|---|---|
| 動作 1 | 讀 P-07-pagemap 頁面區塊規格 |
| 動作 2 | 確認使用者是否明確要求 |
| 動作 3 | 若是 → 執行並在交付摘要標示 |
| 動作 4 | 若不明確 → 反問確認 |

### Q9：使用者要求新增狀態編輯入口

| 面向 | 動作 |
|---|---|
| 動作 1 | 檢查 C-02-rules 的職責對照 |
| 動作 2 | 若入口不符 → 提醒使用者 |
| 動作 3 | 建議合併至 settlements |

### Q10：使用者要求自建 Modal

| 面向 | 動作 |
|---|---|
| 動作 1 | 提醒 C-02-rules Modal 統一規則 |
| 動作 2 | 提供「用 ui/modal.js」方案 |
| 動作 3 | 若堅持 → 記錄為例外並解釋原因 |

### Q11：使用者要求加側邊欄群組

| 面向 | 動作 |
|---|---|
| 動作 1 | 讀 constants.js 的 SIDEBAR_GROUPS |
| 動作 2 | 在陣列中加新群組 + `roles` 陣列 |
| 動作 3 | 不需改 sidebar.js（自動過濾） |
| 動作 4 | 更新 P-07-pagemap + P-08-uispec |

### Q12：使用者要求改某角色可見範圍

| 面向 | 動作 |
|---|---|
| 動作 1 | 找到對應群組的 `roles` 陣列 |
| 動作 2 | 加 / 移除角色 |
| 動作 3 | 更新 docs（P-07 + P-08） |

### Q13：使用者要求改頁面標題 / 副標題

| 面向 | 動作 |
|---|---|
| 動作 1 | 提示使用者「可從 settings 個人化 Tab 自行編輯」 |
| 動作 2 | 若需改預設 → 改 page-metadata-registry.js |
| 動作 3 | 不需改 HTML（page-engine 自動套用） |

### Q14：方案規模看起來很大（≥ 5 檔）

| 面向 | 動作 |
|---|---|
| 動作 1 | **先跑 5 問自檢** |
| 動作 2 | **先掃描實際檔數**（grep） |
| 動作 3 | **先檢查現有 API 複用** |
| 動作 4 | **先考慮集中層強制** |
| 動作 5 | 若仍 ≥ 5 檔 → 逐檔解釋必要性 |
| 動作 6 | 交付摘要必附「最小改動對比」 |

### Q15：Token 狀態顯示（新增）

| 面向 | 動作 |
|---|---|
| 情境 | 每次回覆交付完成 |
| 動作 1 | 回覆結尾顯示 Token 狀態 |
| 動作 2 | 依 C-02 §0.5 格式 |
| 動作 3 | 🟢 ≥ 50% / 🟡 20~49% / 🔴 < 20% |
| 動作 4 | 若 🔴 → 提供新對話開場白 |
