## 一、用途

| 項目 | 說明 |
|---|---|
| 問題 | AI 對 Token 剩餘量的估算不準確，常低估 |
| 解法 | 使用「平方累積公式」反推實際消耗 |
| 目標 | 累積數據後校正估算，使誤差 < 10% |

---

## 二、參考公式

### 2.1 對話輸入總量

輸入（累積） = k × N² / 2

| 符號 | 說明 |
|---|---|
| k | 每輪平均新增 token（含上傳 + 回覆） |
| N | 對話輪數 |

**原理**：每一輪都會重新處理之前所有歷史，因此總輸入量隨輪數平方增長。

### 2.2 輸出總量

輸出 = 全部回覆的 token 總和（不乘輪數）

### 2.3 上下文窗口需求

上下文窗口需求 = 全部上傳內容 + 全部回覆

**不乘輪數**，因為窗口只需容納當前對話歷史。

### 2.4 計費總量

約為「上下文窗口需求」的 30~40 倍（因每輪重複處理歷史）。

### 2.5 換算參考

| 檔案類型 | 每行 token |
|---|---|
| .md 表格 | ~18 |
| .md 敘述 | ~12 |
| .js 程式碼 | ~15 |
| .css | ~8 |
| .html | ~10 |
| .json | ~10 |

## 三、記錄格式

每次「階段性總結」時，新增一筆記錄：

| 欄位 | 說明 |
|---|---|
| 批次 | 當前批次號 |
| 對話輪數 N | 從上次總結到本次總結的輪數 |
| 每輪平均新增 k | 全部上傳 + 回覆 ÷ N |
| 輸入累積 | k × N² / 2 |
| 輸出總量 | 全部回覆 token 和 |
| 估算剩餘 % | AI 顯示的最低剩餘百分比 |
| 實際狀態 | 使用者反饋 |
| 誤差 | 估算 % − 實際 % |
| 校正係數 | 下次估算乘數 |

## 四、累積記錄

### B32-1（本次）

| 項目 | 值 |
|---|---|
| 對話輪數 N | ~20 |
| 每輪平均新增 k | ~12K |
| 輸入累積 | 12K × 20² / 2 ≈ 2.4M |
| 輸出總量 | ~300K |
| 估算剩餘 % | 曾顯示 < 5% |
| 實際狀態 | 仍可運作（新 1M 窗口） |
| 誤差 | −60% |
| 校正係數 | 2.5x |

---

## 五、校正公式

| 項目 | 公式 |
|---|---|
| 輸入累積 | k × N² / 2 |
| 輸出總量 | 直接加總 |
| 上下文窗口需求 | 全部上傳 + 全部回覆 |
| 計費總量 | 上下文窗口需求 × 35（經驗值） |

**估算消耗** = 輸入累積 + 輸出總量
