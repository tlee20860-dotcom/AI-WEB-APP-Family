# C-06 Token 消耗紀錄表

最後更新：B30-6
版本：v1.2
用途：持續修正 Token 估算，提升準確度

---

## 一、用途

| 項目 | 說明 |
|---|---|
| 問題 | AI 對 Token 剩餘量的估算不準確，常低估 |
| 解法 | 每次階段總結記錄「輸入字數」與「輸出字數」，反推實際消耗 |
| 目標 | 累積數據後校正估算公式，使誤差 < 10% |

---

## 二、記錄格式

| 欄位 | 說明 |
|---|---|
| 批次 | 當前批次號 |
| 對話輪數 | 從上次總結到本次總結的輪數 |
| 上傳字數 | 使用者上傳檔案的總字元數（估計） |
| 交付字數 | AI 交付檔案的總字元數（估計） |
| 估算剩餘 % | AI 在對話中顯示的最低剩餘百分比 |
| 實際狀態 | 使用者反饋的真實 Token 狀況 |
| 誤差 | 估算 % − 實際 %（負值代表低估） |
| 校正係數 | 下次估算乘數 |

---

## 三、累積記錄

### B30-6（本次）

| 項目 | 值 |
|---|---|
| 對話輪數 | ~60 |
| 上傳字數 | ~180,000 |
| 交付字數 | ~150,000 |
| 估算剩餘 % | 曾顯示 3% |
| 實際狀態 | 仍充足（最後顯示 82%） |
| 誤差 | −79% |
| 校正係數 | 2.5x |

---

## 四、校正公式（初版）

| 項目 | 係數 |
|---|---|
| 上傳字數 | × 1.0 |
| 交付字數 | × 1.2 |
| 對話往返 | × 1.0 |

**估算消耗** = 上傳字數 × 1.0 + 交付字數 × 1.2 + 輪數 × 500

## 六、記錄方法

| 步驟 | 動作 |
|---|---|
| 1 | 使用者說「階段性總結」 |
| 2 | AI 讀取本檔，找到上次記錄 |
| 3 | 統計本次對話輪數、上傳字數、交付字數 |
| 4 | 新增一筆記錄到 §三 |
| 5 | 重新計算校正係數，更新 §五 |
