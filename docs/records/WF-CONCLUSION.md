## 二、設計結論

### 2.1 編號系統與 API 統一（B34-4 定案）
1. **統一端點**：廢棄所有獨立 CRUD 端點，統一由 `POST /api/entity-create` 處理。
2. **編號生成**：由前端遍歷現有資料取得最大編號 +1。

### 2.2 專案重組與體系對齊（B34-5 定案）
1. **紀錄檔重組**：專案技術文件保留 `P-*`，紀錄檔全面轉為 `WF-*`。
2. **領域資料抽離**：通用 Web App 規則已抽至體系 `W-00 ~ W-07`。

### 2.3 SPA 架構與後端極簡化（2026-10-22 定案）
1. **前端 14 檔架構**：舊版 129 個檔案重構為 7 個 `app-*.js` 核心模組。
2. **後端 2 檔架構**：合併為 `[[path]].js` 與 `_api-core.js`。

### 2.4 模組化重構與智能機械風格（2026-10-23 定案）
1. **廢棄巨型 SPA**：因單檔破千行導致 AI 交付截斷與功能遺漏，廢棄 14 檔架構。
2. **模組化架構**：採用 **「純函數渲染 (UI = f(State)) + 事件委託」**，拆分為 30+ 個精簡檔案。
3. **視覺重構**：全站 CSS 從「家庭暖陽」改為「智能機械風格（深色/霓虹青）」。
4. **功能補齊**：補齊 `funds-allocation.js`、`settings.js` 四卡、`admin.js` 帳號管理。
