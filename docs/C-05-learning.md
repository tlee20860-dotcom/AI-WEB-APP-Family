## 二、教訓（依時間倒序）

### [L-013] 未閱讀現有路徑就給出檔案放置建議

| 項目 | 內容 |
|---|---|
| 場景 | 使用者要更換 icon，我未確認專案結構就建議放根目錄 |
| 錯誤 | 沒有先檢查 `sw.js` 裡已有的 `'./icons/icon.svg'` 路徑 |
| 正確 | 任何涉及「檔案路徑」的建議，必須先閱讀 `sw.js`、`manifest.json` 或相關 HTML |
| 規則 | C-02 §十二 + C-07 §三 |

### [L-012] 排查單一帳號問題時未使用「對照組」

| 項目 | 內容 |
|---|---|
| 場景 | 用戶 `ken` 登入新庫後，看不到資料，一直顯示權限不足 |
| 錯誤 | 陷入修復 `ken` 的思維慣性，花大量時間清快取、改 SW、改檔名，未用全新帳號測試 |
| 正確 | 單一帳號異常時，先用全新帳號（或無痕 + 新帳號）登入測試；若新帳號正常，100% 是舊帳號快取問題 |
| 規則 | C-07 §二 |

### [L-011] CF Pages Functions 不支援 process.env

| 項目 | 內容 |
|---|---|
| 場景 | 後端需依環境切換 Firebase DB |
| 錯誤 | 用 `process.env.DB_TARGET` → CF Pages 讀不到 |
| 正確 | 從 handler 參數 `{ env }` 取，呼叫 `initConfig(env)` |
| 規則 | C-02 §十一 |

### [L-010] 移除 export 導致依賴模組崩潰

| 項目 | 內容 |
|---|---|
| 場景 | 重構 `_config.js` 時移除 `FIREBASE_DB_URL` export |
| 錯誤 | 其他 `_*.js` 仍 import → 模組載入失敗 → 所有 API 報錯 |
| 正確 | 用 `export let` + live binding，保持舊引用相容 |
| 規則 | C-02 §五 |

### [L-009] 交付時 backtick 嵌套未自檢

| 項目 | 內容 |
|---|---|
| 場景 | 交付 md 檔（含內層 code block） |
| 錯誤 | 外層與內層都用 3 backtick → code block 提前關閉 |
| 正確 | 掃描內層 backtick 數 → 外層 = 內層最多 + 1 |
| 規則 | C-02 §六 |

### [L-008] 自我引入 bug

| 項目 | 內容 |
|---|---|
| 場景 | 修改既有邏輯 |
| 錯誤 | 未檢查全鏈路影響 |
| 正確 | 交付前檢查上游 / 下游 |
| 規則 | C-02 交付前檢查 |

### [L-007] 全站結構改動未完整掃描

| 項目 | 內容 |
|---|---|
| 場景 | 統一多頁 HTML 結構 |
| 錯誤 | 只改部分頁，漏 3 頁 |
| 正確 | 改前完整掃描所有目標頁 |
| 規則 | C-02 5 問自檢 |

### [L-006] 動態注入未清空既有內容

| 項目 | 內容 |
|---|---|
| 場景 | JS 動態改文字 |
| 錯誤 | 只加新內容，未清空舊的 |
| 正確 | 先 textContent = '' 再注入 |
| 規則 | C-02 禁止事項 |

### [L-005] 動態值用快照

| 項目 | 內容 |
|---|---|
| 場景 | 元件需顯示動態值 |
| 錯誤 | 由呼叫端傳快照 |
| 正確 | 內部讀狀態（AppState 等） |
| 規則 | C-02 禁止事項 |

### [L-003] 未檢查現有 API 複用

| 項目 | 內容 |

| 規則 | C-02 5 問自檢 |

### [L-002] 統一誤解為各頁都改
