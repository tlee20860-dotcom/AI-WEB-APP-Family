# C-04 交付格式

最後更新：B29-7
版本：v1.0
用途：跨專案通用的交付規範

---

## 一、交付三部分

| 部分 | 格式 |
|---|---|
| 檔案路徑 | 標題 `## 📁 檔案路徑` + 獨立 code block |
| 分隔標題 | 標題 `## 📄 檔案內容` |
| 檔案內容 | code block，附語言標示 |

**語言標示**：

| 副檔名 | 標示 |
|---|---|
| .js | js |
| .md | md |
| .json | json |
| .css | css |
| .html | html |
| .txt | text |

---

## 二、backtick 嵌套規則

| 內層最多 backtick | 外層 backtick |
|---|---|
| 3 個 | 4 個 |
| 4 個 | 5 個 |
| 5 個 | 6 個 |
| N 個 | N + 1 個 |

**規則**：外層 = 內層最多 + 1

---

## 三、END OF FILE 標記

**每個檔案最後必加**：

| 元素 | 內容 |
|---|---|
| 分隔線 | ═══（39 個） |
| 標題 | END OF FILE |
| File | File: {路徑} |
| Version | Version: {版本} |
| Batch | Batch: {批次} |
| 註解符號 | 依檔案類型 |

**註解符號**：

| 檔案 | 符號 |
|---|---|
| .js / .css | /* ... */ |
| .md | /* ... */ 或 <!-- ... --> |
| .html | <!-- ... --> |
| .json | 不支援（不用） |

---

## 四、批次交付

**結構**：

| 部分 | 內容 |
|---|---|
| 批次標題 | `# 📦 B{nn}：第 {N} 波（{X} 檔）` |
| 版本資訊 | `版本 v{nn}` + `批次 B{nn}` |
| 逐檔交付 | 依「三部分」交付 |
| 交付摘要 | 表格 |
| 最小改動對比 | 表格 |
| 交付前自我檢查 | 表格 |
| 下一步 | 說明 |

---

## 五、檔案路徑格式

| 情況 | 寫法 |
|---|---|
| 一般 | `## 📁 檔案路徑` + code block（純文字） |
| 路徑區塊特性 | 無語言標示、只放路徑、相對根目錄 |

---

## 六、禁止事項

| 禁止 | 說明 |
|---|---|
| 只給 diff | 必完整 |
| 用「...」「同上」 | 完整列出 |
| 多檔合併 code block | 每檔獨立 |
| 含內層 code block 用 3 backtick | 外層 = 內層 + 1 |
| 忘 END OF FILE | 必加 |
| 檔案 > 500 行 | 拆檔 |

| 檢查項 | 狀態 |
|---|---|
| 路徑清晰 | |
| 內容完整 | |
| 含 END OF FILE | |
| backtick 嵌套正確 | |

### 程式碼層

| 檢查項 | 狀態 |
|---|---|

### 結構層

## 八、交付摘要必附 3 欄位

| 欄位 | 內容 |
|---|---|
| 改動檔案數 | N |
| 最小改動路徑 | 如何得出 |
| 為何不是 N-1 | 為何不能再少 |

---

## 九、更新清單流程

**使用者說「需要更新清單」**：

| 步驟 | AI 動作 |
|---|---|
| 1 | 列「所有已交付批次」 |
| 2 | 問「已部署到哪個批次？」 |
| 3 | 列「該批次後所有最新版檔案」 |

**格式**：`B{批次} ← 路徑`

---

## 十、多批交付

**若單次無法容納**：

| 步驟 | 動作 |
|---|---|
| 1 | 分批（每批 2~4 檔） |
| 2 | 標「第 N/M 批」 |
| 3 | 使用者回「繼續」交下一批 |
| 4 | 每批完整 |

**檔數建議**：

| 檔案行數 | 每批檔數 |
|---|---|
| < 200 行 | 3~4 檔 |
| 200~400 行 | 2 檔 |
| > 400 行 | 1 檔 |
