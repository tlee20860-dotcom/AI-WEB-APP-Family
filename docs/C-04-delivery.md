# C-04 交付格式

最後更新：B29-9b
版本：v1.1
用途：跨專案通用的交付規範

---

## 一、交付三部分

| 部分 | 格式 |
|---|---|
| 檔案路徑 | 標題 `## 📁 檔案路徑` + 獨立 code block |
| 分隔標題 | 標題 `## 📄 檔案內容` |
| 檔案內容 | code block，附語言標示 |

**語言標示**：

| 副檔名 | 標示 |
|---|---|
| .js | js |
| .md | md |
| .json | json |
| .css | css |
| .html | html |
| .txt | text |

---

## 二、backtick 嵌套規則

| 內層最多 backtick | 外層 backtick |
|---|---|
| 3 個 | 4 個 |
| 4 個 | 5 個 |
| 5 個 | 6 個 |
| N 個 | N + 1 個 |

**規則**：外層 = 內層最多 + 1

**強制檢查**（依 C-02 §六）：交付前掃描內層 backtick 數，決定外層。

---

## 三、END OF FILE 標記

**每個檔案最後必加**：

| 元素 | 內容 |
|---|---|
| 分隔線 | ═══（39 個） |
| 標題 | END OF FILE |
| File | File: {路徑} |
| Version | Version: {版本} |
| Batch | Batch: {批次} |
| 註解符號 | 依檔案類型 |

**註解符號**：

| 檔案 | 符號 |
|---|---|
| .js / .css | /* ... */ |
| .md | /* ... */ 或 <!-- ... --> |
| .html | <!-- ... --> |
| .json | 不支援（不用） |

---

## 四、批次交付

**結構**：

| 部分 | 內容 |
|---|---|
| 批次標題 | `# 📦 B{nn}：第 {N} 波（{X} 檔）` |
| 版本資訊 | `版本 v{nn}` + `批次 B{nn}` |
| 逐檔交付 | 依「三部分」交付 |
| 交付摘要 | 表格 |
| 最小改動對比 | 表格 |
| 交付前自我檢查 | 表格 |
| 下一步 | 說明 |

---

## 五、檔案路徑格式

| 情況 | 寫法 |
|---|---|
| 一般 | `## 📁 檔案路徑` + code block（純文字） |
| 路徑區塊特性 | 無語言標示、只放路徑、相對根目錄 |

## 六、常見錯誤操作修正（11 項）

### 錯誤 1：只交付 diff

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 給 diff 或部分內容 |
| 正確做法 | 交付完整檔案 |
| 理由 | AI 讀取需完整上下文 |

### 錯誤 2：用「...」「同上」

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 中間省略，用「...」 |
| 正確做法 | 完整列出 |
| 理由 | 使用者複製貼上需完整 |

### 錯誤 3：多檔合併一個 code block

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 一個 code block 含多個檔案 |
| 正確做法 | 每檔獨立區塊 |
| 理由 | 使用者需分開存檔 |

### 錯誤 4：含內層 code block 用 3 backtick

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 外層用 3 backtick 但內容含 3 backtick |
| 正確做法 | 外層 = 內層最多 backtick + 1 |
| 理由 | 避免提前關閉 |

### 錯誤 5：用 code block 示範「含 code block 的格式」

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 用 code block 示範含 code block 的東西 |
| 正確做法 | 用表格說明規則（見 C-02 §六） |
| 理由 | 示範本身會造成嵌套 |

### 錯誤 6：忘記 END OF FILE 標記

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 檔案末尾沒有標記 |
| 正確做法 | B20 起所有交付加標記 |
| 理由 | 檢查完整性與版本 |

### 錯誤 7：檔案 > 500 行

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 單檔超過 500 行 |
| 正確做法 | 拆檔 |
| 理由 | 一次 text 可交付 |

### 錯誤 8：忘記更新 file-manifest

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 交付後沒更新 file-manifest |
| 正確做法 | 交付後立即更新 |
| 理由 | 下次「更新清單」需正確資料 |

### 錯誤 9：自建 Modal（0.20）

| 面向 | 說明 |
|---|---|
| 錯誤做法 | `document.createElement('div')` + `class="modal-overlay"` |
| 正確做法 | 用 `openModal(id)` / `closeModal(id)` |
| 理由 | 統一 ESC / backdrop / stack |
| 例外 | 無 |

### 錯誤 10：未確認刪除區塊（0.22）

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 重構時順手移除區塊 |
| 正確做法 | 讀 page-map.md 核對；若有疑義反問 |
| 理由 | 版面是使用者可見契約 |

### 錯誤 11：filters 放 UI 控制變數（P21 教訓）

| 面向 | 說明 |
|---|---|
| 錯誤做法 | `filters.hideCompleted = true` |
| 正確做法 | `state.hideCompleted`（獨立） |
| 理由 | applyFilters 會把非 row 欄位誤當過濾條件 |

## 七、檔案大小操作建議

| 類型 | 若超標 | 處理 |
|---|---|---|
| Page Schema | > 300 | 抽 customMount 邏輯至 lib |
| Block | > 300 | 抽共用邏輯至 lib |
| Lib | > 250 | 拆為多個 lib |
| Engine | > 500 | 拆引擎 |
| Functions API | > 800 | 拆 handler |

---

## 八、命名操作建議

| 類型 | 慣例 | 範例 |
|---|---|---|
| 檔案 | kebab-case | `expense-modal.js` |
| 類別 | PascalCase | `ExpenseModal` |
| 公開函式 | camelCase | `openExpenseModal` |
| 常數 | UPPER_SNAKE_CASE | `MAX_LEN` |
| 私有 / 內部 | `_leadingUnderscore` | `_render()` |
| CSS class | kebab-case | `view-toggle-group` |

**AI 優先例外**：內部區域變數可極簡（`_r`, `_m`, `_h`）。

## 九、多批交付

**若單次回應無法容納**（依 C-02 §0）：

| 步驟 | 動作 |
|---|---|
| 1 | 分批（每批 2~4 檔） |
| 2 | 標「第 N/M 批」 |
| 3 | 使用者回「繼續」交下一批 |
| 4 | 每批完整 |

**檔數建議**：

| 檔案行數 | 每批檔數 |
|---|---|
| < 200 行 | 3~4 檔 |
| 200~400 行 | 2 檔 |
| > 400 行 | 1 檔 |

## 十、更新清單流程

**使用者說「需要更新清單」**：

| 步驟 | AI 動作 |
|---|---|
| 1 | 列「所有已交付批次」 |
| 2 | 問「已部署到哪個批次？」 |
| 3 | 列「該批次後所有最新版檔案」 |

**格式**：`B{批次} ← 路徑`

## 十一、每波交付標準流程

| 步驟 | 動作 |
|---|---|
| 1 | 讀 progress 確認當前批次 |
| 2 | 讀 file-manifest 檔案清單 |
| 3 | 依相依性排序交付 |
| 4 | 每檔交付後自我檢查 |
| 5 | 更新 file-manifest |
| 6 | 更新 progress |
| 7 | 回報摘要 + 下一步 |

## 十二、新規則操作指引

### 12.1 編輯入口職責分離（C-02）

**檢查表**：

| 情境 | 動作 |
|---|---|
| 新增「編輯狀態」入口 | 讀 P-07-pagemap「各頁可編輯欄位」 |
| 若不符 | 提醒使用者，建議合併至 settlements |
| 支出 Modal 需分模式 | 用 `mode: 'data' \| 'settle'` |

### 12.2 Modal 統一（C-02）

**標準流程**：

| 步驟 | 動作 |
|---|---|
| 1 | 用 `openModal(id)` 開啟 |
| 2 | 用 `closeModal(id)` 關閉 |
| 3 | 若需 destroy → `destroyModal(id)` |
| 4 | ESC / backdrop 由 modal.js 自動處理 |

**禁止**：
- 自建 `div.modal-overlay`
- 手動加 `.active` class
- 不入 modal stack

### 12.3 Action 契約（C-02）

**決策表**：

| 需求 | 做法 |
|---|---|
| 只用引擎預設按鈕 | 傳 `hooks.onEdit` / `hooks.onDelete` |
| 只用自訂按鈕 | 傳 `hooks.customActions`（引擎自動跳過預設） |
| 兩者都要 | 傳 `disableBuiltinActions: false` + `customActions` |

### 12.4 版面規格保護（C-02）

**改版面流程**：

| 步驟 | 動作 |
|---|---|
| 1 | 讀 P-07-pagemap「頁面區塊規格」 |
| 2 | 列出「變更前後對照」 |
| 3 | 待使用者確認 |
| 4 | 交付時在摘要標示 |

**允許 / 禁止**：

| 動作 | 允許 |
|---|---|
| 改區塊內部實作 | ✅ |
| 新增區塊（標示） | ✅ |
| 使用者明確要求刪除 | ✅ |
| 未確認刪除區塊 | ❌ |
| 未確認改容器 ID | ❌ |

### 12.5 backtick 嵌套（C-02 §六）

**交付前強制檢查**：

| 步驟 | 動作 |
|---|---|
| 1 | 掃描內層 backtick 數 |
| 2 | 外層 = 內層最多 + 1 |
| 3 | 交付摘要標示「嵌套檢查 ✅」 |

### 12.6 Token 不足處理（C-02 §0）

| 情境 | 動作 |
|---|---|
| Token 足夠 | 交付完，問「是否繼續下一批？」 |
| Token 不足 | 提示 + 提供新對話開場白 |
